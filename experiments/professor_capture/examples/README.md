# 실제 요청 2건의 CSV 예시

2026-10-02 `professor-capture-kur0_jzl` 성공 실행에서 client1의 요청 1·2만 골랐다. 합성 패킷이나 새 실행 결과가 아니다. 원본 200요청/2,000특징행 가운데 일부이며 학습 데이터셋으로 사용하기 위한 표본 수는 아니다.

| 요청 | 최종 응답 본문 | 임시 라벨 |
|---|---:|---|
| client1 요청 1 | 3,205,631 B | elephant |
| client1 요청 2 | 19,510 B | mice |

- `requests.csv`: 위 요청의 정답·추적 정보 2행. `final_bytes`와 `label`은 정답이며 조기 모델 입력이 아니다.
- `features.csv`: 같은 두 요청에 대해 N=1..10, 총 20행. `sample_id`로 정답과 연결한다. 초기 N이 다른 행도 같은 요청에서 나온 것이다.
- `feature-columns.json`: 입력 허용 열. `sample_id`, IP/포트, 최종 크기/FCT를 입력에 섞지 않는다.

첫 요청과 두 번째 요청의 초기 특징이 비슷할 수 있다는 점도 원본 그대로 보존했다. 이 예시는 모델의 예측 성공이나 학습 가능성을 증명하지 않는다. 네트워크 상태가 달라지면 같은 크기의 요청이라도 간격/패킷 수는 달라질 수 있다.

원본 pcap SHA-256: `0c8af192213f5e5bf413465462447a79a5c9c6a3efe797165b44bcb1a602f96e`. pcap 전체는 약 303 MB로 이 예시에 포함하지 않았다. pcap 전처리를 직접 재현하려면 상위 README의 생성·캡처 절차를 실행하거나, pcap·manifest·요청 로그가 모두 포함된 실행 폴더를 사용한다.
